# v1.4.10 — LVM swap cleanup hotfix

`obj08-11` reached 100% in grading but failed during `lab finish`.

The active training swap was an LVM LV. `swapon --show=NAME` exposed it as a
device-mapper path (`/dev/dm-N`), while the reset helper compared the output to
the friendly LVM path (`/dev/rhcsa_vgswap/rhcsa_lvswap`). The comparison
therefore failed, `swapoff` was skipped, and the still-active swap kept the LV,
VG, and `/dev/vde1` busy.

v1.4.10 changes cleanup to state/identity-based behavior:

- enumerate the actual active swap devices reported by `swapon`;
- resolve each active swap's label with `blkid`;
- deactivate only the labels reserved by OBJ08:
  `RHCSA08SWAP`, `BASWAP08`, `LVSWAP08`, and `FINALSWAP08`;
- preserve the system swap regardless of whether it appears as a friendly LVM
  path or `/dev/dm-N`;
- add a release gate that rejects a return to friendly-path string comparison.

This fix also proactively covers the LVM swap used by `obj08-12`.
