# v1.4.6 — interrupted LVM recovery hotfix

The v1.4.5 diagnostics proved that `/dev/vdc1` remained busy because the
training mapping `rhcsa_vgdata-rhcsa_lvdata` was still active.

The previous reset only removed a training VG when a preliminary discovery
probe succeeded. That condition is unreliable after an interrupted,
partially-created LVM setup.

The reset now explicitly targets only the known `rhcsa_*` training LVs and VGs,
deactivates/removes those mappings first, and uses a device-mapper fallback
restricted to names beginning with `rhcsa_`.

Only after the training LVM mappings are gone does the reset wipe signatures
and reread the partition table.
