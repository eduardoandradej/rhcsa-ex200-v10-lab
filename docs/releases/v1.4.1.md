# v1.4.1 — OBJ08 safety-bootstrap hotfix

Corrects `obj08-01` and hardens all Objective 08 lab starts.

## Cause

The storage guard and reset utilities were installed only by
`ansible/prepare-objective08.yml`.

A targeted command such as:

`tests/integration-reference.sh obj08-01`

does not use the full-objective integration wrapper, so `lab start` could reach
the per-lab setup before `/usr/local/sbin/rhcsa-storage-guard` existed.

The objective preflight also contained a malformed Ansible loop expression for
the scratch-device validation command.

## Fix

- storage safety helpers now live in reusable files under `ansible/files/`;
- every OBJ08 `setup.yml` installs the guard and reset helper before any safety
  check;
- `prepare-objective08.yml` uses the same reusable helper files;
- the scratch-device loop now correctly uses `{{ item }}`;
- targeted OBJ08 reference integrations automatically run the objective
  preflight;
- a release gate rejects future OBJ08 labs that depend on an external,
  previously executed bootstrap.

The `/dev/vda` deny rule and scratch-device allowlist are unchanged.
