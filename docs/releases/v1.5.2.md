# v1.5.2 — OBJ08-02 GPT partition grader portability hotfix

The global 77-lab regression exposed a grader portability issue in `obj08-02`.

The reference state was correct:

- `/dev/vdb` had a GPT;
- partition 1 was exactly 1 GiB;
- the GPT partition name was `data08`;
- the saved `lsblk` evidence showed `data08`;
- privileged udev data exposed `ID_PART_ENTRY_NAME=data08`;
- no filesystem existed on the partition.

However, a later unprivileged `lsblk` query returned an empty `PARTLABEL`.
The old grader used that unprivileged `lsblk PARTLABEL` value as the source of
truth, so it reported a false failure even though the on-disk GPT metadata was
correct.

v1.5.2 changes only the grader contract:

- GPT table, partition size, and GPT partition name are read from privileged
  `parted -sm ... unit B print`;
- privileged `lsblk` remains responsible for topology and filesystem state;
- the grader no longer depends on `lsblk PARTLABEL`;
- a release gate prevents reintroducing that dependency.

The student task, setup, reference solution, storage reset, and expected final
state are unchanged.
