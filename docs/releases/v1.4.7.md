# v1.4.7 — timeout containment hotfix

The `obj08-09` diagnostics proved the original failure mode: the bastion-side
180-second timeout ended the direct `ansible-playbook` process while an SSH
descendant and the remote Ansible module remained alive. The remote `lvcreate`
then survived for almost two days, holding the LVM write lock and device-mapper
mapping open.

v1.4.7 fixes the cause at two layers.

- The lab runner now starts commands in their own process session and, on
  timeout, terminates the entire local Ansible/SSH process group. It escalates
  to SIGKILL after a short grace period and returns status 124 instead of an
  uncaught Python timeout traceback.
- Destructive setup commands in `obj08-09` and `obj08-10` are independently
  bounded on `servera` with `timeout --signal=TERM --kill-after=2s 30s`.
- QA reference storage commands are also bounded so regression testing cannot
  leave an indefinitely-running remote storage operation.
- The reset helper now reports the real timeout return code instead of the
  incorrect `rc=0` message observed during recovery.
