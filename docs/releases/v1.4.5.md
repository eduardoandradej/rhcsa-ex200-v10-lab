# v1.4.5 — OBJ08 bounded reset and recovery hotfix

This release changes the reset design rather than retrying the same cleanup.

## Problem

A failed storage setup can leave a scratch disk with a partial partition map.
The previous reset then used several silent, unbounded synchronization
operations, including a final bare `udevadm settle`. In this state, recovery
could itself hang, forcing the operator to interrupt it.

## Changes

- every potentially blocking reset action is time-bounded;
- reset prints its current recovery stage instead of suppressing all context;
- training mounts and swaps are cleaned only from the OBJ08 allowlist;
- training VGs are removed explicitly and never include `rhel_servera`;
- child signatures and disk signatures are wiped;
- `partx -d`, `blockdev --rereadpt`, and `partprobe` are used as bounded kernel
  partition-map recovery mechanisms;
- `udevadm settle` is bounded and is no longer trusted as the only completion
  condition;
- a 15-second explicit `lsblk` verification loop proves that child partitions
  disappeared;
- if the kernel still reports partitions, reset fails with `lsblk` diagnostics
  instead of hanging;
- all remaining OBJ08 automation/reference uses of `udevadm settle` receive a
  timeout.

The system disk deny rule and scratch-device allowlist are unchanged.
